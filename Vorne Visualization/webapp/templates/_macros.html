Piece counts are not yet reliable

Reject count is derived as infeed minus good count rather than from scanned reject reasons, and the reject-event log is empty across the entire history. Where the good-count sensor registers more pieces than the infeed sensor saw, rejects go negative.

Data runs to the last closed hour{% for d in devices %}{% if snap.history[d].last_closed_end %}{{ ' (' if loop.first else ', ' }}{{ d }} {{ snap.history[d].last_closed_end|local }}{{ ')' if loop.last }}{% endif %}{% endfor %}; the hour still in progress is not included. Available = running ÷ scheduled. Performance = ideal ÷ running. Both use full one-hour records only, where partial records distort the rate. Availability counts planned stops in the denominator, unlike the common OEE convention (run ÷ (run + unplanned)), so it reads lower than a textbook figure for the same hours. Calendar use = scheduled ÷ elapsed, and every hours column, use all closed records, including the long overnight not-scheduled blocks. Down h = unplanned stop.
